## 💡 コンセプト・ゲーム概要

3Dフィールドを探索しながら通常エネミーを多彩なアクションで倒し、敵から得たお金でステータスを強化して、最終ステージのボス討伐を目指すゲームです。

- **多彩な3Dアクション**:
  - アタック、ジャンプ攻撃、スライドアタックに加え、無敵時間を活用した回避アクションを実装。敵の攻撃を見極めて反撃する手触りを追求しました。
- **ショップでのキャラクター育成（キャラビルド）**:
  - 倒した敵から集めたお金で「最大HP」「攻撃力」「移動速度」「回避性能」などを自由に強化可能。
- **手応えのあるボス戦とエフェクト演出**:
  - 複数の攻撃パターンを持つボスとの緊張感あるバトル。Effekseerを使ったエフェクトでバトルの迫力を高めています。

## 🛠 技術的なこだわり・アピールポイント

### 1. Unityのような3段階の当たり判定をC++で自作
- **取り組んだ理由**:
  - ゲームエンジンを使わない環境で、Unityのように「当たった瞬間」「当たり続けているとき」「離れた瞬間」の3つの状態に分けた当たり判定を、C++で自分で作ってみたいと考え挑戦しました。
- **工夫した点・実装内容**:
  - 当たり判定の処理が散らからないよう、当たり判定自体の管理は `Collider` クラス、全体の衝突管理は `CollisionManager` クラスに分けました。
  - 攻撃ヒット時や被ダメージ時の処理も1つのクラスに詰め込まず、効果ごとにクラスを分けて見やすく、手入れしやすい構造にしました。
  - 画面上に当たり判定用の球体をワイヤーフレームで可視化し、当たり判定の発生タイミングや持続を調整しやすいデバッグ環境も整えました。

### 2. クラス設計の勉強を兼ねた「ステート管理とコンポーネント管理」
- **取り組んだ理由**:
  - しっかりとしたクラス設計を学ぶため、1つの巨大なクラスに処理を詰め込まず、部品ごとに分けて管理する設計を目指しました。
- **工夫した点・実装内容**:
  - キャラクターの行動や敵のAIには「ステートパターン」を使い、待機・攻撃・移動・回避などの状態ごとに分けて管理しました。
  - コライダーや武器、3Dモデルなどは「コンポーネント指向」を取り入れて作成しました。
  - 「1つの部品がバグで壊れても、他の部分に影響を出さない」ことを意識して、それぞれのクラス同士を切り離して設計しました。

## 🔧 課題と問題解決

| 直面した問題 | 原因 | 解決策（アプローチ） |
| :--- | :--- | :--- |
| **アニメーションの強制解除・重複バグ** | 次のアクションの入力が入った際、現在のアニメーション再生状態を無視して次の処理が走ってしまい、再生中のモーションが途中で切れたり二重に再生されたりしていた。 | ステート側で現在の再生状況や遷移可能タイミングの判定・調整を行って解消。その解決の過程で「ガード形式（事前条件を満たさない入力は早めに弾く書き方）」を知り、不要な割り込みを確実に防げるようになった。 |
| **ショップの商品・パラメータ追加に伴うコードの肥大化** | アイテムや強化項目のデータ（価格、上昇値、説明文など）をコード内に直接ベタ書きしていたため、データ量が増えるたびにソースコードが長くなり、修正や管理が大変になっていた。 | データをソースコードから切り離し、外部のCSVファイルで管理する方式へ変更。起動時にCSVを読み込んで商品データを生成するようにしたことで、コードを増やさずにパラメータの調整や項目の追加ができるようになった。 |

## 🕹 操作方法

| キー / 入力 | アクション |
| :--- | :--- |
| `W` / `A` / `S` / `D` | 移動 |

| `マウス左クリック` | 攻撃 |
| `E` | 攻撃方法の切り替え |

| `P` | ポーズ |
| `[F5]` / `[F6]` | 【デバッグ】敵を全滅 / ボス戦へ移動 |
